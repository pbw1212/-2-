## 二、现场复跑

```bash
cd 02_D源代码

# 1. 完整流程：继承历史 → 改日期 → 确认保存
python run.py demo --out ../04_D演示

# 2. 换科室：医生依赖检查与“不指定”
python run.py replay --case c05_department_change --events

# 3. 歧义澄清：只说“周五”时按字段追问
python run.py replay --case c09_ambiguous_date --events

# 4. 对照评测（重建两个库与全部日志）
python run.py eval --out ../03_D实验记录与结果

# 5. 测试
python -m unittest discover -s tests -v
```

## 三、演示时要说明的三点

1. **继承不等于替用户决定。** 档案带出的科室和医生是候选，必须随本次复述一起确认；
   用户说“还是上次那位”才是明确引用。
2. **改口靠版本号，而不是靠分支清理。** 任何字段修改都会推进草稿版本，旧确认快照
   随之失效，所以第 2 轮改日期后必须重新复述。
3. **先写库、后播报。** 最坏情况是写成功但没播出来，可以按 registration_id 重播，
   不会出现“用户听到已登记、库里却没有”的情况。

## 四、演示记录（终端输出）

完整输出见同目录 `演示记录.txt`，关键几行如下：

```
用户(turn 1)：还是上次那位，下周四下午
D  → 为您登记复诊：康复科张医生，12月3日下午，对吗？
用户(turn 2)：改成下周五
D  → 为您登记复诊：康复科张医生，12月4日下午，对吗？
用户(turn 3)：对
D  → 已为您登记：康复科张医生，12月4日下午。登记编号 REG-0001。

记录 REG-0001：科室=rehab 医生=d_rehab_zhang 日期=2026-12-04 时段=afternoon
```

复述文本与方案里的例子一致：第 1 轮复述“康复科张医生，下周四下午”，用户改为
“下周五”后只更新日期，最后一句“对”只保存最新版本一次。
