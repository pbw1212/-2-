# D 模块状态与字段清单（第一版）

对应三阶段交付的第一项成果：状态和字段清单。字段名与《全组联调总方案与接口
规范》第一版一致；凡是规范没有覆盖、由 D 自己维护的内容，都标了“D 内部”。

---

## 1. 槽位字段

| 字段 | 中文 | 必填 | 规范值 | 说明 |
| --- | --- | --- | --- | --- |
| `department` | 科室 | 是 | 组内词表 ID，如 `rehab` | 显示名“康复科”由 `lexicon.json` 提供 |
| `date` | 日期 | 是 | `YYYY-MM-DD` | 相对日期按会话参考日解析，参考日回放时固定 |
| `period` | 时段 | 是 | `morning` / `afternoon` | 显示为“上午/下午”；E 负责读法 |
| `doctor` | 医生 | 否 | 组内词表 ID，如 `d_rehab_zhang` | 在“用户指定”或“历史继承”时随本次确认 |

每个槽位除规范值外还记录：

| 属性 | 取值 | 含义 |
| --- | --- | --- |
| `raw` | 字符串 | 用户原表达，例如“下周四” |
| `source` | `user` / `history` / `history_ref` / `none` | 值来源，跨轮保留 |
| `status` | `ok` / `ambiguous` / `candidate` / `needs_check` / `skipped` / `missing` | 见下表 |
| `candidates` | 列表 | 歧义时的候选，每项含 `value/raw/label` |
| `updated_turn` | 整数 | 最近修改发生在第几轮 |
| `note` | 字符串 | 例如“科室变更，原医生不再适用” |

状态含义：

| 状态 | 是否算已填 | 何时出现 | D 的动作 |
| --- | --- | --- | --- |
| `missing` | 否 | 还没有值 | 按固定顺序补问 |
| `ok` | 是 | C 给了明确值 | 可用于复述与保存 |
| `ambiguous` | 否 | C 返回候选，value 为空 | 定向澄清或开放重问 |
| `candidate` | 是 | 档案历史值带入 | 随本次复述一起确认 |
| `needs_check` | 否 | 换科室后医生不再属于新科室 | 追问是否指定医生 |
| `skipped` | 否（不阻塞） | 用户明确说“不指定” | 不再追问，也不写入记录 |

## 2. 草稿字段（D 内部）

| 字段 | 说明 |
| --- | --- |
| `session_id` | 会话标识，与公共字段一致 |
| `registration_id` | 一次登记一个编号，形如 `REG-0001`，库中唯一 |
| `profile_id` | 当前选定的模拟档案，继承历史的前提 |
| `phase` | `idle` / `collecting` / `confirming` / `ended` |
| `revision` | 草稿版本，任何有效修改 +1，旧确认快照随之失效 |
| `pending_field` | 当前正在问的字段（D 内部，用于日志） |
| `snapshot` | 确认快照，见第 3 节 |
| `reprompt_count` | 连续未听清次数，超过 `max_reprompt` 退出 |
| `save_status` | `None` / `saved` / `failed` |
| `ended_reason` | `user_cancel` / `too_many_reprompts` 等 |

---

## 3. 确认快照

| 键 | 说明 |
| --- | --- |
| `revision` | 生成这条确认时的草稿版本 |
| `reply_id` | 这条复述的播报 ID；播报失败重发时会改绑新 ID |
| `confirm_turn` | 预期用来确认的用户轮次（复述轮 + 1） |
| `playback_done` | 该 reply_id 是否已收到 `PLAYBACK_RESULT completed` |
| `fields` | 复述时的字段快照（值 + 来源 + 状态） |

只有“轮次一致 + 版本一致 + 已播完”三条同时满足，`confirm` 才会写库。

---

## 4. 状态机

```
idle ──book/有字段──► collecting ──字段齐全──► confirming ──确认──► ended
  ▲                        │  ▲                    │
  │                        │  └──更正/否认改口─────┘
  └──取消──────────────────┴───────────────────────►
```

| 当前阶段 | 事件 | 下一阶段 | 动作 |
| --- | --- | --- | --- |
| idle | 预约/给字段 | collecting | 建草稿、写字段 |
| collecting | 字段补齐 | confirming | `restate_confirm`（yes_no） |
| collecting | 字段仍缺 | collecting | `ask_<field>` |
| collecting | 有歧义 | collecting | `ask_date` 定向澄清（改进组） |
| collecting | FAQ | 原阶段 | `faq_resume_ask` / `faq_resume_confirm` |
| confirming | `confirm` 且快照有效 | ended | `saved` / `duplicate_ack` |
| confirming | `confirm` 但版本已变 | confirming | 重新复述 |
| confirming | `deny` | collecting | `ask_correction` |
| confirming | 改口 | confirming | 只改对应字段并重新复述 |
| confirming | 写库失败 | confirming | `retry_save` |
| confirming | 播放失败 | 不变 | `retry_playback`（新 reply_id） |
| 任意 | 明确取消 | ended | `cancel_ack`，不写库 |
| 任意 | 连续没听清 | ended | `exit_after_reprompt` |

---

## 5. 动作（`REPLY_REQUEST.action`）

| 动作 | 含义 |
| --- | --- |
| `ask_department` / `ask_date` / `ask_period` / `ask_doctor` | 补问某个字段 |
| `ask_correction` | 确认被否认后问“改哪一项” |
| `restate_confirm` | 完整复述，等待“对/不对” |
| `retry_save` | 写库失败，请用户再说一次确认 |
| `retry_playback` | 播报失败重发，同一文本新 reply_id |
| `faq_answer` / `faq_resume_ask` / `faq_resume_confirm` | 咨询作答并接回登记 |
| `saved` / `duplicate_ack` | 保存成功 / 已保存过 |
| `cancel_ack` | 取消反馈 |
| `reprompt` / `exit_after_reprompt` | 没听清重问 / 重问上限退出 |

---

## 6. 下一轮上下文（`TURN_CONTEXT`）

| 键 | 取值 | 用途 |
| --- | --- | --- |
| `dialog_phase` | `idle` / `collecting` / `confirming` | A/B/C 判断当前阶段 |
| `question_type` | `open` / `targeted` / `yes_no` | B 决定端点策略，A 可选热词 |
| `expected_slots` | 数组，可为空 | 本轮期望字段 |
| `expected_slot` | 单值或 `null` | `expected_slots` 只有一个时派生 |
| `reference_date` | `YYYY-MM-DD` | 相对日期解析基准，回放固定 |
| `registration_id` / `draft_revision` / `profile_id` | 可选 | 日志核对用 |
| `question_text` | 可选 | D 刚刚问出的那句话，便于联调排查 |
| `pending_field` | 可选 | 当前字段 |

确认轮的 `question_type` 为 `yes_no`，`expected_slots` 为空数组；换科室后追问
医生时 `expected_slots=["doctor"]`。

## 7. 本地库表

| 表 | 关键列 | 说明 |
| --- | --- | --- |
| `registrations` | `registration_id`（主键）、`session_id`、`profile_id`、`department`、`doctor`、`visit_date`、`period`、`created_at`、`snapshot_json`、`source_json` | 一次确认一条 |
| `dialog_log` | `session_id`、`turn_id`、`phase`、`action`、`detail`、`created_at` | 工程日志 |

`source_json` 形如 `{"department": "history_ref", "doctor": "history_ref",
"date": "user", "period": "user"}`，用于回答“这个值是从哪来的”。
