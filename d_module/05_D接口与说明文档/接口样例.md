# D 模块接口样例（第一版，与接口规范对齐）

所有事件都是 JSON，公共字段为：

```json
{"schema_version": 1, "event": "...", "session_id": "s01",
 "turn_id": 2, "emitted_mono_ms": 4870, "payload": {...}}
```

`turn_id` 表示用户轮次，会话首个用户轮次为 1；有开场播报时可用 0。
`emitted_mono_ms` 是本机单调时钟毫秒，只用于排序和耗时统计。

下面是一段真实回放日志（`03_D实验记录与结果/logs/c03_inherit_history_improved.jsonl`）
的节选，可以直接作为联调样例。

---

## 1. 会话开始：D → A/B/C

```json
{"schema_version": 1, "event": "TURN_CONTEXT", "session_id": "c03", "turn_id": 1,
 "emitted_mono_ms": 93171265,
 "payload": {"dialog_phase": "idle", "question_type": "open",
             "expected_slots": [], "expected_slot": null,
             "reference_date": "2026-11-24",
             "question_text": "请先告诉我您要复诊的科室、日期和时段。"}}
```

## 2. A → D：档案建议（可选）

```json
{"schema_version": 1, "event": "PROFILE_SUGGESTION", "session_id": "c03",
 "turn_id": 0, "emitted_mono_ms": 93171265,
 "payload": {"profile_id": "p001", "match_status": "matched"}}
```

`match_status` 可用 `matched` / `low_score` / `none`。D 只在档案存在时才读取
它的历史科室和医生；低分或缺失时按未选择档案处理，由用户重新选择。

## 3. C → D：理解结果（预约 + 历史引用 + 相对日期）

```json
{"schema_version": 1, "event": "NLU_RESULT", "session_id": "c03", "turn_id": 1,
 "emitted_mono_ms": 93171281,
 "payload": {"intent": "provide_slot", "status": "ok",
             "history_ref": "last_doctor",
             "slots": {"date":   {"value": "2026-12-03", "raw": "下周四", "status": "ok"},
                       "period": {"value": "afternoon", "raw": "下午", "status": "ok"}}}}
```

- `intent`：`faq` / `book` / `provide_slot` / `correct` / `confirm` / `deny` / `cancel` / `unknown`
- `status`：`ok` / `ambiguous` / `no_match` / `no_input` / `error`
- `history_ref`：`last_doctor` 或 `last_visit`，表示“还是上次那位”
- 未提及的字段直接省略；整轮无字段时 `slots` 为空对象

歧义日期（C 只听到“周五”）：

```json
{"intent": "provide_slot", "status": "ambiguous",
 "slots": {"date": {"value": null, "raw": "周五", "status": "ambiguous",
                    "candidates": [{"value": "2026-11-27", "raw": "本周五", "label": "本周五"},
                                   {"value": "2026-12-04", "raw": "下周五", "label": "下周五"}]}}}
```

FAQ 命中：

```json
{"intent": "faq", "status": "ok", "slots": {},
 "faq_id": "faq_what_to_bring",
 "answer_text": "复诊请带上医保卡、就诊卡，还有上次的检查报告和正在吃的药盒。",
 "retrieval_score": 0.91}
```

## 4. D → E：播报请求

```json
{"schema_version": 1, "event": "REPLY_REQUEST", "session_id": "c03", "turn_id": 1,
 "emitted_mono_ms": 93171281,
 "payload": {"reply_id": "r-c03-01-01",
             "reply_text": "为您登记复诊：康复科张医生，12月3日下午，对吗？",
             "action": "restate_confirm", "dialog_phase": "confirming"}}
```

`action` 取值见 `状态与字段清单.md` 第 5 节。E 只负责把 `reply_text` 读出来，
不解析业务字段；`reply_id` 用于播放队列和去重。

## 5. D → A/B/C：下一轮是“是/否”确认

```json
{"schema_version": 1, "event": "TURN_CONTEXT", "session_id": "c03", "turn_id": 2,
 "emitted_mono_ms": 93171281,
 "payload": {"dialog_phase": "confirming", "question_type": "yes_no",
             "expected_slots": [], "expected_slot": null,
             "reference_date": "2026-11-24",
             "question_text": "为您登记复诊：康复科张医生，12月3日下午，对吗？",
             "registration_id": "REG-0003", "draft_revision": 1,
             "profile_id": "p001"}}
```

## 6. E → D：播报完成

```json
{"schema_version": 1, "event": "PLAYBACK_RESULT", "session_id": "c03", "turn_id": 1,
 "emitted_mono_ms": 93171281,
 "payload": {"reply_id": "r-c03-01-01", "status": "completed"}}
```

失败时：

```json
{"payload": {"reply_id": "r-c03-01-01", "status": "failed",
             "error_code": "device_busy"}}
```

D 收到失败会用**新的 reply_id** 重发同一段文本（`action=retry_playback`），
并把确认快照改绑到新回复；旧回复的迟到 `completed` 会被忽略。

## 7. 确认与保存

用户说“对”：

```json
{"schema_version": 1, "event": "NLU_RESULT", "session_id": "c03", "turn_id": 2,
 "payload": {"intent": "confirm", "status": "ok", "slots": {}}}
```

D 校验“轮次 + 版本 + 已播完”后写库，再播报：

```json
{"reply_text": "已为您登记：康复科张医生，12月3日下午。登记编号 REG-0003。",
 "action": "saved"}
```

重复确认返回 `action=duplicate_ack`，文本为“这次登记已经保存过了…”，不会新增记录。

## 8. 换科室后的字段依赖

用户说“换成骨科”，D 清空不属于骨科的医生并追问：

```json
{"event": "REPLY_REQUEST", "payload": {
  "reply_text": "换到骨科后，原来的医生不再适用。请问还要指定医生吗？可以说不指定。",
  "action": "ask_doctor", "dialog_phase": "collecting"}}
```

对应的下一轮上下文：

```json
{"event": "TURN_CONTEXT", "payload": {
  "dialog_phase": "collecting", "question_type": "targeted",
  "expected_slots": ["doctor"], "expected_slot": "doctor", ...}}
```

---

## 9. 对接步骤（给 C 和 E）

1. **C**：按第 3 节的 `payload` 结构发送 `NLU_RESULT`，`turn_id` 用 D 在
   `TURN_CONTEXT` 里给的下一个轮次；相对日期按 `reference_date` 解析。
2. **E**：收到 `REPLY_REQUEST` 后播报，播完发 `PLAYBACK_RESULT`，`reply_id`
   原样带回；失败时带 `error_code`，D 会重发。
3. **A/B**：按 `TURN_CONTEXT.question_type` 选择端点策略；`expected_slots`
   只有一个元素时读 `expected_slot`。
4. 联调时把 `nlu_sim.parse` 换成 C 的真实结果、把回放里的自动播报换成 E 的
   `PLAYBACK_RESULT`，`policy.py` 不需要改动。
