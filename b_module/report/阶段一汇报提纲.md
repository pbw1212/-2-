### 2.3 结果（v2 口径）

| 策略 | 总截断率 | 带停顿开放式轮截断率 | 短答轮延迟中位数 |
| :--- | ---: | ---: | ---: |
| 固定 300 ms | 6/29 = 21% | **100%** | 180 ms |
| 固定 600 ms | 6/29 = 21% | **100%** | 480 ms |
| 固定 900 ms | 5/29 = 17% | 83% | 780 ms |

| 自适应二（再加临时文本） | 0/29 = 0% | **0%** | **470 ms** |

> 「截断率」= 决策点早于人工标注轮末（容差 1 帧 = 20 ms）的轮数 ÷ 触发轮数。

## 3. 逐页规格

### P1 · 定位（40 秒）

**标题**：`B 模块：判断用户这一轮什么时候说完`

**一句话主张**：整机里 A 只负责把音频变成文字，"说完了没有"由 B 判断，B 是唯一发停止信号的模块。

**正文要点（3 条，不超过）**：

1. 位置：`A（流式转写）→ B（端点）→ A 冲刷尾块 → C（理解）→ D（对话）→ E（播报）`；B 同时接收 D 给的"这一轮问的是什么类型"。
2. **端点主权归 B**：A 的识别器自带自动端点已经关闭，否则两套端点会抢着截断。
3. 对外只发一个事件：`TURN_STOP`，**每轮只发一次**，带 `decision_audio_ms` 和触发原因。

**素材**：自画 5 个方框的链路图（B 用红色描边/填充高亮），箭头按上面顺序；右上角可加一条小注"引用组内接口规范 v1"。

**讲稿**：见第 4 节第一段。

### P2 · 问题（60 秒）

**标题**：`单点阈值没有解：要么砍断用户，要么让所有人白等`

**一句话主张**：同一个固定静音阈值，无法同时满足"句中长停顿不截断"和"短答要快"。

**正文要点（3 条）**：

1. 老年患者句中停顿很常见——"我想约康复科……下周四下午"。**我们设计的停顿是 650–1000 ms，但检测器实际看到 820–1220 ms**（语音尾音衰减到阈值以下后，检测器就认为安静了）。
2. 固定 600 ms：6 条带停顿样本 **100% 被截断**，后半句直接丢失。
3. 固定阈值要 0% 截断必须开到 1500 ms，代价是用户只说一个"对"也要白等 **1.38 s**。

**素材**：
* 左：能量曲线 `results/annotation/dev_01.png`（能直接看到 1000 ms 的停顿与紫色轮末线）
* 右：主图左栏 `results/figure_tradeoff.png`（裁左半部分即可）

**讲稿**：见第 4 节第二段。

### P3 · 方案（60 秒）

**标题**：`三级策略：每一级只加一种新证据`

**一句话主张**：固定阈值 → 加对话上下文 → 再加临时转写，逐级对照，才能说清"收益来自哪一条证据"。

**正文做成表格（就放这张）**：

| 策略 | 额外使用的证据 | 取值 | 触发原因 |
| :--- | :--- | :--- | :--- |
| 固定阈值（基线） | 无 | 300 / 600 / 900 / 1200 / 1500 ms | `fixed_silence` |
| 自适应一 | D 给的问题类型 | 开放式 **1500**、定向 **600**、是非 **600** | `adaptive_silence` |
| 自适应二 | 临时转写 + 200 ms 稳定窗 | 稳定短答 **450**、续说线索 **1500**、上限 1500 | `adaptive_silence` |

**表下加两行小字（重要）**：

* `open=1500` **不是拍的**：6 条停顿样本的可观测静音是 820–1220 ms，只有 1500 档能 0 截断。
* 短答规则只在**是非/定向**轮生效；开放式轮即使识别出"康复科"也不缩短，否则"我想约康复科……"会被砍。

### P4 · 数据与可复现（50 秒）

**标题**：`29 条真实工程数据，一条命令即可复现全部结果`

**一句话主张**：数据不新录、真值有口径、结果可重跑，并且我们自己找出并修掉了两个错误。

**正文要点（3 条）**：

1. 复用 A 已入库的 29 条录音，自己重建"整轮音频"——**分段 wav 自带 700–800 ms 尾静音，直接拼接会把 1000 ms 的停顿变成 1779 ms**，所以要先裁到语音边界再精确插入 `pause_ms`。
2. 真值口径：−60 dBFS、连续 3 帧、段间隔 ≥300 ms，容差 1 帧；做了**听审台**（片段跨过轮末、边界在正中间）供人工确认。
3. 自己找出的两个错误：① 尾音被硬裁（平均 122 ms，人工听审发现）；② `open` 档定成 900 是错的（扫描发现，改 1500）。

### P5 · 结果与下一步（60 秒）

**标题**：`0% 截断下，短答等待从 1.38 s 降到 0.47 s`

**一句话主张**：自适应策略在保持与固定 1500 ms 相同的安全性的同时，把短答的等待砍掉约 **900 ms**。

**正文要点（3 条）**：

## 4. 讲稿（约 1 分 35 秒，逐字）

> **【P1】** 我负责 B 模块，端点检测，就是判断用户这一轮什么时候说完。整机链路里，A 只负责把音频变成文字，什么时候结束由 B 决定，A 自带的自动截断已经关掉了。
>
> **【P2】** 为什么需要单独一个模块？面向老年患者，句中长停顿很常见——"我想约康复科……下周四下午"。固定 600 毫秒一定砍掉后半句；把阈值开到 1.5 秒，用户只说一个"对"又要白等一秒半。这里还有个关键测量：**我们设计的停顿是 650 到 1000 毫秒，但检测器实际看到的静音是 820 到 1220 毫秒**，因为语音尾音衰减到阈值以下，检测器就已经当成安静了。
>
> **【P3】** 所以做三级策略，每一级只加一种新证据。固定阈值做基线；自适应一加入 D 给的问题类型，开放式等 1500、定向和是非等 600；自适应二再用已经到达的临时转写，稳定短答压到 450 毫秒。开放档取 1500 不是拍的，是上面那个 820–1220 毫秒的分布算出来的。
>
> **【P4】** 数据用 A 已入库的 29 条录音，我写了可复现的回放器，29 条乘 7 档一共 203 次回放。过程中自己找出了两个错误：一是重建音频时把每个字的尾音硬裁掉了，人工听审听出来，平均丢了 122 毫秒；二是开放档一开始定成 900，被扫描数据纠正成 1500。
>
> **【P5】** 结果是：要做到 0% 截断，固定阈值必须 1500 毫秒，代价是短答白等 1.38 秒；自适应同样 0% 截断，短答只等 470 毫秒，省了大约 900 毫秒。局限也说清楚：参数是在这 29 条上定的，没有留出集，第二阶段补真实老年语音后要重新划分再测。

## 5. 预判问答

| 老师可能问 | 回答要点 |
| :--- | :--- |
| 为什么不用现成的 VAD？ | VAD 回答"这一帧有没有人说话"，B 回答"这一轮说完了没有"；后者要静音累计 + 对话上下文 + 文本证据，并且保证每轮只发一次停止信号。 |
| 29 条能说明什么？ | 说明**流程可复现、趋势清楚**，不宣称统计显著性；样本是合成音，第二阶段补真人。 |
| 参数是不是对着这 6 条调的？ | 是，这是真实局限，不掩饰：没有留出集。但取值来自可观测静音的分布（820–1220 ms），不是试错；12/5 重新按说话人划分。 |
| 设计停顿 800 ms，900 ms 阈值为什么还会截断？ | 因为设计停顿 ≠ 可观测静音，差 20–220 ms；这是本阶段最有价值的测量结论。 |
| 那个尾音问题怎么回事？ | 初版按 −45 dBFS 裁分段尾音，平均丢了 122 ms、最多 220 ms；听审发现后改 −60 dBFS，并加了回归测试防止回退；真值后移后截断率也从偏乐观回到真实值。 |
| 1500 ms 上限为什么不算 timeout？ | `timeout` 在协议里对应下游的 error（设备/解码故障）；等待上限是**正常轮末**，缺的字段交给 D 补问。 |
| 自适应二有多少收益？ | 确认轮 760→620 ms；但只有 1 条样本，池中位数只差 10 ms，这一项要靠第二阶段更多样本验证，现在不宣称显著。 |
| 怎么保证不重复发 TURN_STOP？ | 状态机进入"已结束"后丢弃所有输入；迟到旧轮次按轮次号丢弃；都有单元测试。 |
